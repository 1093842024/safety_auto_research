## 1. RL for LLM Safety: 基础与前沿

### 1.1 为什么RL是安全审核的关键技术

传统安全审核依赖监督学习（SFT），但SFT有三个根本局限：

**局限一：静态分布假设**
- SFT假设训练数据和部署数据同分布
- 对抗攻击不断演化，训练分布永远落后于部署分布
- RL可以在线交互，持续适应新攻击模式

**局限二：缺乏探索机制**
- SFT只能学习标注数据中的模式
- 无法主动发现未知风险
- RL通过探索-利用（exploration-exploitation）机制主动发现盲区

**局限三：优化目标单一**
- SFT优化交叉熵损失，与最终安全指标（准召、F1）存在gap
- RL可以直接优化安全指标，或设计复杂的奖励函数
- 可以同时优化多个目标（安全、可用性、延迟）

### 1.2 GRPO: 当前LLM安全RL的主导算法

GRPO（Group Relative Policy Optimization）是2025-2026年LLM安全RL训练的主流算法，被MAGIC、CHASE、AIR、T²-GRPO等多篇论文采用。

**核心思想**：
- 对每个prompt，从当前policy采样一组response（group）
- 用group内response的相对表现计算优势函数
- 不需要critic/value network，降低训练复杂度

**数学形式**：
J_GRPO(θ) = E[q ~ P(Q), {o_i} ~ π_θ_old(O|q)]
    [1/G Σ_i min(π_θ(o_i|q)/π_θ_old(o_i|q) * A_i,
     clip(π_θ(o_i|q)/π_θ_old(o_i|q), 1-ε, 1+ε) * A_i) - β D_KL(π_θ || π_ref)]

其中 A_i = (r_i - mean(r)) / std(r) 是group内的相对优势

**GRPO vs PPO 对比**：

| 维度 | PPO | GRPO |
|------|-----|------|
| Value Network | 需要 | 不需要 |
| 训练稳定性 | 中（依赖value network质量） | 高（group内相对比较） |
| 计算成本 | 高（需要同时训练actor+critic） | 中（只需actor） |
| 样本效率 | 高（利用value function） | 中（依赖group size） |
| 实现复杂度 | 高 | 中 |
| 安全领域采用 | 较少 | 主流（MAGIC、CHASE等） |

### 1.3 奖励建模：安全RL的核心挑战

奖励函数设计是安全RL中最关键也最困难的部分。以下是当前主流方法：

**方法一：二元奖励**
- 简单：安全=+1，不安全=-1
- 问题：缺乏细粒度，无法区分不同程度的风险
- 适用：初步实验

**方法二：乘法奖励（Multiplicative Reward）**
- CHASE采用：R = R_bypass × R_intent
- R_bypass：绕过审核的程度（0-1）
- R_intent：保留原始有害意图的程度（0-1）
- 优势：同时优化两个维度，避免"绕过但丢失意图"的无效攻击

**方法三：基于Rubric的奖励（RUBAS方法）**
- 将agent行为分解为4个维度：
  - 工具使用安全（tool-use safety）
  - 论证安全（argument safety）
  - 回复安全（response safety）
  - 有用性（helpfulness）
- 每个维度有结构化rubric，提供细粒度可解释奖励
- 优势：可解释性强，可以定位具体问题

**方法四：软标签奖励（SWARM方法）**
- 用连续概率标签 p ∈ [0,1] 替代二元安全分类
- 奖励 = f(p) 是概率的连续函数
- 优势：保留不确定性信息，避免信息损失

**方法五：字典学习多样性奖励（RETA方法）**
- 在标准安全奖励外，增加多样性奖励
- 使用字典学习（dictionary learning）从模型激活中提取多样特征
- 优势：鼓励模型学习多样化的安全策略

### 1.4 RL Scaling Laws for Content Moderation

Scaling RL for Content Moderation (arXiv:2512.20061) 系统研究了RL在内容审核中的扩展规律：

**关键发现**：

1. **Sigmoid-like Scaling**：RL性能随训练数据、rollout、优化步数平滑提升后逐渐饱和
   - 初期：快速提升（数据效率高）
   - 中期：稳定提升
   - 后期：逐渐饱和

2. **100x数据效率**：RL比SFT的数据效率高约100倍
   - SFT需要大量标注数据
   - RL可以通过reward signal从少量数据中学习
   - 在标注稀缺场景下特别有价值

3. **策略推理提升显著**：RL在需要复杂策略推理的任务上提升最大
   - 简单模式匹配任务：RL提升有限
   - 需要多步推理的任务：RL提升显著
   - 对抗检测任务：RL提升最大

4. **RL vs SFT 对比**：
   - SFT：学习"说什么"（模仿标注分布）
   - RL：学习"做什么"（优化最终目标）
   - 安全审核需要两者结合：SFT建立基础能力，RL优化安全决策

**对我们的启发**：
- RL可以用于蓝队Agent的持续优化——在对抗环境中提升审核能力
- 高数据效率意味着可以用有限的对抗样本训练更好的审核器
- RL的sigmoid scaling可以帮助预测投入产出比，规划训练预算


## 2. 多Agent RL对抗安全框架

### 2.1 MAGIC: 多轮多Agent RL对抗游戏

**论文**：MAGIC: A Co-Evolving Attacker-Defender Adversarial Game for Robust LLM Safety (arXiv:2602.01539)

#### 2.1.1 核心思想

MAGIC将LLM安全对齐形式化为一个**对抗非对称博弈**（adversarial asymmetric game），其中：
- **攻击者（Attacker）**：学习将安全查询重写为欺骗性提示，绕过目标LLM的安全护栏
- **防御者（Defender）**：优化以识别和拒绝对抗性输入

两者通过多轮RL同时进化，形成**共同进化**（co-evolution）动力学。

#### 2.1.2 技术架构

```
┌─────────────────────────────────────────────────────────────┐
│                    MAGIC 框架架构                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  每轮迭代：                                                   │
│                                                             │
│  ┌──────────────┐     ┌──────────────┐                     │
│  │  攻击者策略 π_A  │────→│  生成对抗提示   │                     │
│  │  (RL优化)      │     │  x_adv = π_A(x) │                     │
│  └──────────────┘     └──────┬───────┘                     │
│                              │                              │
│                              ▼                              │
│  ┌──────────────┐     ┌──────────────┐                     │
│  │  防御者策略 π_D  │←────│  目标LLM响应    │                     │
│  │  (RL优化)      │     │  y = LLM(x_adv) │                     │
│  └──────────────┘     └──────────────┘                     │
│                              │                              │
│                              ▼                              │
│  ┌──────────────┐     ┌──────────────┐                     │
│  │  奖励计算      │────→│  策略更新      │                     │
│  │  R_A, R_D     │     │  π_A, π_D     │                     │
│  └──────────────┘     └──────────────┘                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

#### 2.1.3 攻击者设计

攻击者策略 π_A 学习将安全查询 x 重写为对抗提示 x_adv：

**状态空间**：原始安全查询 x + 历史攻击尝试记录
**动作空间**：提示重写策略（角色扮演、虚构框架、说服改写等）
**奖励函数**：
- R_A = bypass_success × intent_preservation
- bypass_success：是否成功绕过防御者
- intent_preservation：重写后是否保留原始有害意图

**训练算法**：GRPO（Group Relative Policy Optimization）

**关键发现**：
1. 攻击者通过RL可以进化出新颖的组合策略
2. 攻击策略从简单角色扮演进化到复杂的多步诱导
3. 攻击者学会利用防御者的盲区

#### 2.1.4 防御者设计

防御者策略 π_D 学习识别和拒绝对抗输入：

**状态空间**：输入提示 x + 模型内部状态
**动作空间**：接受/拒绝 + 置信度分数
**奖励函数**：
- R_D = correct_refusal + helpful_acceptance
- correct_refusal：正确拒绝有害内容
- helpful_acceptance：正确接受安全内容

**训练算法**：GRPO

**关键发现**：
1. 防御者通过对抗训练获得更强的鲁棒性
2. 防御者学会识别攻击者策略的模式
3. 共同进化使防御者不断适应新攻击

#### 2.1.5 共同进化动力学

MAGIC的核心洞察是攻击者和防御者的共同进化：

```
回合 1: 攻击者使用简单角色扮演 → 防御者轻松识别
回合 5: 攻击者进化出多步诱导 → 防御者开始漏检
回合 10: 防御者学会识别多步诱导 → 攻击者转向新策略
回合 20: 攻击者发现防御者盲区 → 防御者再次适应
...
```

这种共同进化动力学使得安全对齐不再是"一次性"任务，而是持续对抗过程。

#### 2.1.6 对我们的启发

1. **红队-蓝队RL框架**：方向三的红队-蓝队可以直接采用MAGIC的对抗RL框架
2. **共同进化**：红队和蓝队应该同时进化，而非红队固定后优化蓝队
3. **奖励设计**：乘法奖励（bypass × intent）可以用于红队Agent的奖励设计
4. **GRPO训练**：蓝队Agent可以使用GRPO在对抗环境中持续优化

### 2.2 CHASE: 共同进化对抗红蓝队训练

**论文**：CHASE: Adversarial Red-Blue Teaming for Improving LLM Safety using Reinforcement Learning (arXiv:2606.05523)

#### 2.2.1 核心思想

CHASE（Co-evolutionary Hardening through Adversarial Safety-Escalation）提出闭环红蓝队训练框架，红队和蓝队通过RL共同进化。

#### 2.2.2 技术架构

**红队（Red Team）**：
- 使用GRPO训练，优化目标是生成能绕过蓝队的对抗提示
- 奖励函数：R_red = bypass_effectiveness × intent_fidelity
- 模板无关（template-free）的RL探索

**蓝队（Blue Team）**：
- 两阶段GRPO训练：
  - 阶段一：标准安全对齐GRPO
  - 阶段二：对抗环境GRPO（面对红队生成的对抗样本）
- 拒绝采样SFT（rejection-sampled SFT）作为补充

#### 2.2.3 关键结果

1. **StrongREJECT降低43.2%**：在强对抗攻击下，有害响应率降低43.2%
2. **0% False Refusal**：在提升安全性的同时，不增加对安全内容的误拒率
3. **模板无关RL探索**：红队通过RL发现的新攻击模式可以跨攻击家族迁移
4. **攻击原语恢复**：RL探索可以恢复潜在的攻击原语（latent attack primitives）

#### 2.2.4 模板无关RL探索

CHASE最关键的创新是**模板无关的RL探索**：

- 传统红队：使用预定义的攻击模板（如"扮演角色X"）
- CHASE红队：RL从零开始学习攻击策略，不依赖模板
- 优势：可以发现模板未覆盖的新攻击模式
- 机制：红队的动作空间是自然语言空间，通过RL探索有效攻击模式

**攻击原语迁移**：
- RL探索发现的攻击模式可以跨攻击家族迁移
- 例如：从"角色扮演"攻击中学到的模式可以迁移到"虚构框架"攻击
- 这意味着红队RL训练的投资具有泛化价值

#### 2.2.5 对我们的启发

1. **两阶段蓝队训练**：先标准安全对齐，再对抗环境优化
2. **拒绝采样SFT**：对抗训练后，用拒绝采样SFT巩固学习成果
3. **模板无关探索**：红队Agent应该具备自由探索能力，而非仅使用预定义模板
4. **攻击原语迁移**：红队RL训练的价值不仅在于当前攻击，还在于发现可迁移的攻击模式

### 2.3 MAGIC vs CHASE 对比

| 维度 | MAGIC | CHASE |
|------|-------|-------|
| 框架类型 | 多轮多Agent RL对抗游戏 | 共同进化红蓝队训练 |
| 红队算法 | GRPO | GRPO |
| 蓝队算法 | GRPO | 两阶段GRPO + 拒绝采样SFT |
| 奖励设计 | 乘法奖励 | 乘法奖励 |
| 模板依赖 | 部分依赖 | 模板无关 |
| 关键创新 | 非对称博弈形式化 | 攻击原语迁移 |
| 计算成本 | 高（多轮对抗） | 高（两阶段训练） |
| 安全提升 | 显著 | 显著（43.2% StrongREJECT降低） |
| 误拒控制 | 未明确 | 0% False Refusal |

### 2.4 自对弈与反思经验回放

**论文**：Be Your Own Red Teamer: Safety Alignment via Self-Play and Reflective Experience Replay

#### 2.4.1 核心思想

不需要独立红队模型，让LLM自己扮演红队和蓝队，通过自对弈（self-play）和反思经验回放（reflective experience replay）实现安全对齐。

#### 2.4.2 技术架构

**自对弈阶段**：
1. LLM生成对抗提示（红队模式）
2. LLM审核对抗提示（蓝队模式）
3. 记录成功/失败案例

**反思经验回放阶段**：
1. 从经验池中采样失败案例
2. LLM反思为什么失败
3. 从反思中学习改进策略

#### 2.4.3 关键优势

1. **无需独立红队模型**：降低系统复杂度
2. **自我反思**：模型从自身错误中学习
3. **经验回放**：避免灾难性遗忘

#### 2.4.4 对我们的启发

1. 自对弈可以作为方向三的轻量级起点——不需要训练独立红队模型
2. 反思经验回放可以融入数据回流引擎
3. 自对弈+独立红队的混合方案可能最优

### 2.5 系统化RL-Jailbreaking研究

**论文**：A Systematic Investigation of RL-Jailbreaking in LLMs

#### 2.5.1 核心发现

1. RL可以系统化地学习越狱策略，而非随机尝试
2. RL越狱的成功率随训练步数平滑提升
3. RL越狱发现的漏洞往往在多个模型上通用
4. RL越狱策略可以迁移到未见过的攻击类别

#### 2.5.2 对我们的启发

1. RL越狱研究为红队Agent提供了理论基础——RL是系统化发现漏洞的有效方法
2. 红队Agent应该使用RL而非随机搜索
3. 漏洞的跨模型通用性意味着红队RL训练的投资回报率高


## 3. RL驱动的审核模型优化

### 3.1 Scaling RL for Content Moderation: 深度分析

**论文**：Scaling Reinforcement Learning for Content Moderation with Large Language Models (arXiv:2512.20061)

#### 3.1.1 实验设置

- **任务**：政策违规内容检测（policy-grounded moderation）
- **模型**：多个LLM（7B-70B参数范围）
- **训练方法**：RL（PPO/GRPO）vs SFT
- **评估**：多个安全benchmark

#### 3.1.2 核心发现详解

**发现一：RL的Sigmoid Scaling行为**

RL性能随训练数据量的变化呈现Sigmoid曲线：
```
性能
  ↑
  |     ____________________
  |    /                    \
  |   /                      \
  |  /                        \
  | /                          \
  |/____________________________\__→ 训练数据量
  初期快速提升    中期稳定    后期饱和
```

- 初期（0-1000样本）：性能快速提升，每增加100样本提升2-3%
- 中期（1000-10000样本）：稳定提升，每增加1000样本提升0.5-1%
- 后期（>10000样本）：逐渐饱和，边际收益递减

**发现二：100x数据效率**

在相同性能水平下，RL所需标注数据量约为SFT的1/100：
- SFT达到80% F1需要10000标注样本
- RL达到80% F1只需要100标注样本 + 1000次rollout
- 原因：RL通过reward signal从rollout中学习，不需要人工标注每个样本

**发现三：策略推理任务提升最大**

RL在不同类型任务上的提升幅度：
- 简单模式匹配（关键词检测）：+2-5%
- 语义理解（判断内容是否违规）：+5-15%
- 策略推理（理解复杂政策并应用）：+15-30%
- 对抗检测（识别对抗改写）：+20-40%

#### 3.1.3 实践指导

**何时使用RL vs SFT**：
- 标注数据充足（>10000样本）：SFT即可，RL边际收益有限
- 标注数据稀缺（<1000样本）：RL优先，数据效率优势明显
- 对抗环境：RL必须，SFT无法适应动态攻击
- 策略频繁变化：RL必须，SFT需要重新标注

**RL训练配置建议**：
- Group size：8-16（GRPO）
- 学习率：1e-6 to 5e-6
- 训练步数：500-2000
- Rollout数量：每个训练步8-16
- KL惩罚系数 β：0.01-0.05

### 3.2 RUBAS: 基于Rubric的Agent安全RL

**论文**：RUBAS: Rubric-Based Reinforcement Learning for Agent Safety (arXiv:2606.04051)

#### 3.2.1 核心思想

RUBAS提出基于rubric的RL框架，将agent行为分解为多个安全维度，每个维度有结构化评分标准。

#### 3.2.2 四维安全Rubric

**维度一：工具使用安全（Tool-Use Safety）**
- 评估agent调用工具时的安全性
- 是否调用未授权工具
- 是否传递敏感参数
- 是否在危险上下文中调用工具

**维度二：论证安全（Argument Safety）**
- 评估agent推理过程中的安全性
- 是否在推理中泄露敏感信息
- 是否使用不安全的前提假设
- 推理链是否包含有害内容

**维度三：回复安全（Response Safety）**
- 评估agent最终输出的安全性
- 是否包含有害内容
- 是否泄露敏感信息
- 是否鼓励不安全行为

**维度四：有用性（Helpfulness）**
- 评估agent在安全前提下的有用程度
- 是否过度拒绝（误杀）
- 是否提供替代方案
- 是否在安全边界内最大化帮助

#### 3.2.3 奖励计算

每个维度有5级评分（1-5），最终奖励为加权和：
R = w_1 × R_tool + w_2 × R_argument + w_3 × R_response + w_4 × R_helpfulness

权重可以根据业务需求调整：
- 高风险场景：w_tool = 0.4, w_response = 0.4, w_argument = 0.15, w_helpfulness = 0.05
- 一般场景：w_tool = 0.25, w_response = 0.25, w_argument = 0.25, w_helpfulness = 0.25

#### 3.2.4 对我们的启发

1. **Rubric设计**：可以为内容审核Agent设计类似的安全rubric
2. **维度分解**：将审核质量分解为多个可量化维度
3. **权重调节**：不同业务场景可以调节不同维度的权重
4. **可解释性**：Rubric评分提供了审核决策的可解释性

### 3.3 AIR: Anchor Invariance Regularization

**论文**：Towards Context-Invariant Safety Alignment for Large Language Models (AIR, arXiv:2605.20994)

#### 3.3.1 核心思想

AIR提出上下文不变安全对齐（context-invariant safety alignment），使用GRPO训练模型使其安全行为不依赖于表面形式，而是基于底层意图。

#### 3.3.2 技术方法

**Anchor Invariance Regularization**：
- 对每个有害意图，构造多个表面形式不同的变体
- 使用GRPO训练模型对所有变体一致拒绝
- 异构prompt分组（heterogeneous prompt grouping）确保多样性

**训练流程**：
1. 选择一组有害意图
2. 对每个意图，生成N个表面形式不同的变体
3. 使用GRPO训练模型对所有变体一致拒绝
4. 评估：在未见过的变体上测试泛化性

#### 3.3.3 关键结果

1. 上下文不变对齐显著提升对抗鲁棒性
2. 异构prompt分组比同构分组效果好
3. GRPO比PPO更适合上下文不变训练

#### 3.3.4 对我们的启发

1. AIR的上下文不变对齐可以用于蓝队Agent——使其审核不依赖于表面形式
2. 异构prompt分组可以用于构建对抗训练数据
3. GRPO是上下文不变训练的首选算法

### 3.4 轻量安全护栏的RL引导对抗训练

**论文**：Lightweight Safety Guardrails via Synthetic Data and RL-guided Adversarial Training

#### 3.4.1 核心思想

用小模型（<1B参数）实现与大模型相当的安全审核能力，通过合成数据+RL引导的对抗训练。

#### 3.4.2 技术方法

1. **合成数据生成**：使用大模型生成高质量安全训练数据
2. **RL引导对抗训练**：使用RL选择最具挑战性的对抗样本
3. **小模型训练**：在精选数据上训练小模型

#### 3.4.3 关键结果

1. 小模型可以达到甚至超越大模型的安全审核性能
2. RL引导的对抗训练比随机采样更有效
3. 合成数据+RL的组合可以显著降低标注成本

#### 3.4.4 对我们的启发

1. 方向一（轻量实时化）和方向三（多Agent对抗）可以结合
2. RL引导的对抗训练可以用于训练轻量蓝队Agent
3. 合成数据可以解决对抗训练数据不足的问题

### 3.5 RLBF: 带回溯反馈的RL

**论文**：Reinforcement Learning with Backtracking Feedback (RLBF)

#### 3.5.1 核心思想

RLBF在BSAFE基础上引入回溯反馈机制，当模型在后续步骤发现之前的决策错误时，可以回溯修正。

#### 3.5.2 技术方法

1. **前向推理**：模型生成审核决策序列
2. **回溯检测**：在后续步骤检测到矛盾时触发回溯
3. **反馈修正**：回溯到错误点，重新决策
4. **经验存储**：将回溯案例存入经验池

#### 3.5.3 对我们的启发

1. 回溯反馈可以用于仲裁Agent——当发现蓝队判定矛盾时回溯分析
2. 回溯机制可以提升审核的准确性
3. 经验池可以用于持续学习


## 4. Agent安全与工具调用RL

### 4.1 RETA: 推理启用的任务对齐防御

**论文**：Defending against Adaptive Prompt Injection Attacks via Reasoning-enabled Task Alignment (RETA, arXiv:2606.15441)

#### 4.1.1 核心思想

RETA提出推理启用的任务对齐（reasoning-enabled task alignment）防御框架，针对自适应提示注入攻击。

#### 4.1.2 技术架构

**多目标RL优化**：
- 主目标：正确执行用户任务
- 安全目标：拒绝注入指令
- 多样性目标：学习多样化的安全策略

**字典学习多样性奖励**：
- 从模型激活中提取特征字典
- 计算当前策略与字典中已有特征的差异
- 差异越大，多样性奖励越高
- 鼓励模型探索不同的安全策略

#### 4.1.3 关键结果

1. 在6种黑盒自适应攻击下，per-attack ASR保持在10%以下
2. 字典学习多样性奖励显著提升泛化性
3. 推理启用的任务对齐比纯分类防御更鲁棒

#### 4.1.4 对我们的启发

1. **多目标RL**：蓝队Agent可以同时优化多个目标（安全、可用性、一致性）
2. **字典学习多样性**：可以用于红队Agent的多样化攻击生成
3. **推理启用**：审核Agent应该使用推理（CoT）而非直接分类

### 4.2 ToolSafe: 步骤级工具调用护栏

**论文**：ToolSafe: Enhancing Tool Invocation Safety of LLM-based agents via Proactive Step-level Guardrail and Feedback (arXiv:2601.10156)

#### 4.2.1 核心思想

ToolSafe提出步骤级（step-level）工具调用护栏，在agent调用工具的每一步进行实时监控和主动干预。

#### 4.2.2 技术架构

**TS-Bench**：步骤级工具调用安全benchmark
- 覆盖多种工具调用场景
- 标注每个步骤的安全性
- 包含正常和异常工具调用

**步骤级护栏**：
- 实时监控agent的每一步工具调用
- 在工具执行前进行安全检查
- 发现不安全调用时主动干预

**反馈机制**：
- 拦截不安全调用后，提供反馈指导agent修正
- 反馈包含：为什么不安全 + 如何修正

#### 4.2.3 关键结果

1. 有害工具调用减少65%
2. 步骤级干预比输出级干预更有效
3. 反馈机制帮助agent学习安全工具使用

#### 4.2.4 对我们的启发

1. **步骤级审核**：内容审核也可以从"输出级"下沉到"步骤级"
2. **主动干预**：在有害内容生成前拦截，而非生成后检测
3. **反馈机制**：拦截后提供修正指导，而非简单拒绝

### 4.3 T²-GRPO: 回合轨迹GRPO

**论文**：T²-GRPO: A Turn-Trajectory Group Relative Policy Optimization for Caregiver Agents (arXiv:2606.08875)

#### 4.3.1 核心思想

T²-GRPO针对长周期agent任务，将RL优化解耦为两个归一化奖励视野（reward horizons）：
- **回合级（Turn-level）**：即时安全奖励
- **轨迹级（Trajectory-level）**：长期任务完成奖励

#### 4.3.2 技术方法

**双视野奖励**：
- R_turn：每个回合的即时安全评估
- R_trajectory：整个轨迹的任务完成评估
- 最终奖励 = α × R_turn + (1-α) × R_trajectory

**二元硬否决（Binary Hard Veto）**：
- 任何回合的安全违规直接否决整个轨迹
- 即使轨迹最终完成任务，如果中间有安全违规，奖励为0
- 确保安全是硬约束而非软约束

#### 4.3.3 对我们的启发

1. **双视野奖励**：内容审核可以同时考虑"即时安全"和"长期任务完成"
2. **硬否决机制**：任何审核环节的安全违规应该否决整个审核结果
3. **回合级奖励**：可以用于多轮对话审核中的每轮安全评估

### 4.4 Plan-RewardBench: 轨迹级偏好基准

**论文**：Aligning Agents via Planning: A Benchmark for Trajectory-Level Reward Modeling (Plan-RewardBench, arXiv:2604.08178)

#### 4.4.1 核心内容

Plan-RewardBench是专门用于评估agent轨迹级奖励模型的benchmark，覆盖4个维度：
- **Safety Refusal**：安全拒绝能力
- **Tool-Irrelevance**：工具无关性（不调用不必要的工具）
- **Complex Planning**：复杂规划能力
- **Robust Error Recovery**：鲁棒错误恢复

#### 4.4.2 对我们的启发

1. Plan-RewardBench可以用于评估仲裁Agent的奖励模型
2. 轨迹级评估比回合级评估更全面
3. 四个维度可以用于设计审核Agent的评估体系

### 4.5 SWARM: 软标签治理

**论文**：Soft-Label Governance for Distributional Safety in Multi-Agent Systems (SWARM, arXiv:2604.19752)

#### 4.5.1 核心思想

SWARM提出软标签治理框架，用连续概率标签替代二元安全分类，实现分布级安全治理。

#### 4.5.2 治理杠杆

**交易税（Transaction Tax）**：
- 对高风险agent的交易征收额外成本
- 税率与风险概率成正比
- 效果：降低高风险agent的活动频率

**断路器（Circuit Breaker）**：
- 当agent行为超过安全阈值时自动中断
- 阈值可配置
- 效果：防止安全事件升级

**声誉衰减（Reputation Decay）**：
- agent的安全声誉随时间衰减
- 需要持续良好行为维持声誉
- 效果：鼓励持续安全行为

**随机审计（Random Audit）**：
- 随机抽查agent行为
- 审计频率与风险成正比
- 效果：威慑不安全行为

#### 4.5.3 关键发现

1. 严格治理可能降低40%以上福利而不提升安全性
2. 过度内化外部性可能使总福利从+262降至-67
3. 断路器需要仔细校准——过于严格严重损害系统价值

#### 4.5.4 对我们的启发

1. **软标签输出**：仲裁Agent应该输出连续安全分数而非二元判定
2. **治理杠杆**：多Agent审核系统需要可配置的治理机制
3. **安全-福利tradeoff**：需要量化分析安全提升与系统效率的平衡

### 5.2 三个RL训练循环

#### 循环一：红队RL训练

**目标**：训练红队Agent生成高质量对抗样本

**状态空间**：
- 原始安全查询 x
- 历史攻击尝试记录（成功/失败）
- 蓝队Agent的审核反馈
- 当前攻击策略类型

**动作空间**：
- 提示重写策略（角色扮演、虚构框架、说服改写、多步诱导等）
- 攻击强度调节（从轻微改写→深度伪装）
- 目标选择（针对哪个蓝队Agent）

**奖励函数**：
R_red = R_bypass × R_intent + λ × R_diversity

- R_bypass：绕过蓝队审核的程度（0-1）
- R_intent：保留原始有害意图的程度（0-1）
- R_diversity：攻击策略的多样性（基于字典学习）
- λ：多样性权重（0.1-0.3）

**训练算法**：GRPO
- Group size：8
- 学习率：3e-6
- KL惩罚系数 β：0.02
- 每轮训练步数：200

#### 循环二：蓝队RL训练

**目标**：训练蓝队Agent在对抗环境中提升审核能力

**状态空间**：
- 待审核内容 x
- 红队攻击策略类型（如果可识别）
- 历史审核记录
- 当前审核标准配置

**动作空间**：
- 安全判定（safe/unsafe/uncertain）
- 置信度分数（0-1）
- 风险类别分类
- 推理链（CoT）

**奖励函数**：
R_blue = R_correctness + R_calibration + R_efficiency - R_overrefusal

- R_correctness：判定正确性（基于gold label）
- R_calibration：置信度校准质量
- R_efficiency：审核效率（延迟、计算成本）
- R_overrefusal：过度拒绝惩罚（误杀惩罚）

**训练算法**：两阶段GRPO（参考CHASE）
- 阶段一：标准安全对齐GRPO（在标准安全数据集上）
- 阶段二：对抗环境GRPO（面对红队生成的对抗样本）
- 拒绝采样SFT作为补充

#### 循环三：仲裁Agent RL训练

**目标**：训练仲裁Agent综合多蓝队判定做出最优决策

**状态空间**：
- 多个蓝队的判定结果（verdict + confidence + reasoning_chain）
- 蓝队的历史表现记录
- 当前审核标准配置
- 业务场景特征

**动作空间**：
- 最终判定（safe/unsafe/need_review）
- 综合置信度分数
- 判定解释
- 是否需要更多蓝队参与

**奖励函数**：
R_arbiter = R_final_correctness + R_disagreement_resolution + R_efficiency

- R_final_correctness：最终判定的正确性
- R_disagreement_resolution：不一致解决质量
- R_efficiency：仲裁效率

**训练算法**：GRPO
- Group size：4
- 学习率：3e-6
- KL惩罚系数 β：0.01

### 5.4 经验回放池设计

经验回放池是持续学习的基础，需要存储和管理对抗训练数据：

**数据结构**：
```
{
  "query": "原始查询",
  "adversarial_query": "对抗改写后的查询",
  "attack_strategy": "攻击策略类型",
  "blue_judgments": [

}
```

**采样策略**：
- **优先级采样**：高奖励差异的样本优先
- **多样性采样**：覆盖不同攻击策略
- **困难样本采样**：蓝队判定不一致的样本
- **时间衰减**：旧样本权重逐渐降低

### 5.5 可研究点展开

#### 研究点1：红队RL攻击策略进化

**问题**：红队Agent如何通过RL进化出多样化的攻击策略？

**具体实验设计**：
1. 实现红队Agent的GRPO训练框架
2. 设计奖励函数：R_bypass × R_intent + λ × R_diversity
3. 训练红队Agent进化攻击策略
4. 分析：攻击策略的进化轨迹和多样性

**评估指标**：
- 攻击成功率（ASR）随训练步数的变化
- 攻击策略的多样性（基于embedding距离）
- 攻击策略的迁移性（跨蓝队模型）

**预期挑战**：
- 奖励函数设计需要精细调参
- 多样性奖励可能降低攻击质量
- 红队可能过拟合到特定蓝队

#### 研究点2：蓝队对抗RL训练

**问题**：蓝队Agent如何在对抗环境中通过RL持续提升审核能力？

**具体实验设计**：
1. 实现蓝队Agent的两阶段GRPO训练
2. 阶段一：标准安全数据集上GRPO
3. 阶段二：红队生成的对抗样本上GRPO
4. 评估：对抗训练前后的准召变化

**评估指标**：
- 标准测试集上的准召
- 对抗测试集上的准召
- 误拒率（False Refusal Rate）
- 训练稳定性

**预期挑战**：
- 对抗训练可能导致灾难性遗忘
- 误拒率可能上升
- 训练稳定性需要监控

#### 研究点3：仲裁Agent的RL优化

**问题**：仲裁Agent如何通过RL学习最优综合决策策略？

**具体实验设计**：
1. 实现仲裁Agent的GRPO训练
2. 设计状态空间：多蓝队判定 + 历史表现 + 场景特征
3. 训练仲裁Agent优化综合决策
4. 对比：RL仲裁 vs 规则仲裁 vs 投票仲裁

**评估指标**：
- 最终判定准召
- 不一致解决率
- 仲裁延迟
- 与最优贝叶斯决策的差距

**预期挑战**：
- 状态空间设计需要仔细考虑
- 奖励函数需要平衡多个目标
- 仲裁Agent可能过度依赖某个蓝队

#### 研究点4：多目标RL奖励设计

**问题**：如何设计同时优化安全、可用性、效率的多目标奖励函数？

**具体实验设计**：
1. 设计多目标奖励函数
2. 使用Pareto优化方法探索奖励权重空间
3. 分析不同权重组合下的系统行为
4. 推荐最优权重配置

**评估指标**：
- Pareto前沿覆盖率
- 安全-可用性-效率的三维tradeoff
- 权重敏感度分析

**预期挑战**：
- 多目标优化可能难以收敛
- Pareto前沿可能不平滑
- 权重选择需要业务知识

#### 研究点5：经验回放策略优化

**问题**：如何设计最优的经验回放策略加速RL训练？

**具体实验设计**：
1. 实现多种经验回放策略（优先级、多样性、困难样本）
2. 对比不同策略下的训练效率
3. 分析：哪种策略最适合安全审核场景
4. 设计自适应回放策略

**评估指标**：
- 收敛速度（达到目标性能所需的训练步数）
- 最终性能
- 样本效率（每样本的性能提升）

**预期挑战**：
- 回放策略可能引入偏置
- 优先级采样可能导致分布偏移
- 自适应策略需要额外调参

#### 研究点6：跨模型迁移的RL红队

**问题**：红队RL训练发现的攻击模式能否跨模型迁移？

**具体实验设计**：
1. 在模型A上训练红队Agent
2. 将红队Agent迁移到模型B
3. 评估：红队在模型B上的攻击成功率
4. 分析：哪些攻击模式可迁移，哪些不可

**评估指标**：
- 迁移攻击成功率
- 攻击模式相似度
- 迁移效率（需要多少步适应）

**预期挑战**：
- 攻击模式可能过拟合到特定模型
- 迁移可能需要少量微调
- 不同模型的漏洞分布不同

### 8.3 评估协议

**标准评估协议**：
1. 在标准测试集上评估：报告AUROC、F1、精确率、召回率
2. 在对抗测试集上评估：报告ASR、检测率
3. 在误报测试集上评估：报告误拒率
4. 报告95%置信区间（bootstrap 1000次）

**对抗评估协议**：
1. 红队Agent生成N轮对抗样本（N=1000）
2. 蓝队Agent审核对抗样本
3. 仲裁Agent综合判定
4. 报告：ASR、检测率、误拒率
5. 分析：攻击策略分布、蓝队不一致模式

**持续学习评估协议**：
1. 记录初始性能
2. 每轮RL训练后评估
3. 绘制学习曲线
4. 报告：收敛速度、最终性能、样本效率
