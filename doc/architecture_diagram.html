② 后端模块依赖与调用流

谁持有谁、谁调用谁。api.py 暴露 HTTP，内部组合 ControlPlaneService + ResearchStateStore + ClosedLoopOrchestrator；执行面经 PlatformSDK 唯一通道回写控制面。

关键调用链： api.py 持有单例 ControlPlaneService + ResearchStateStore + ClosedLoopOrchestrator。耗时操作（dual-loop / evolution）经后台线程 _drive 执行，通过 ProgressBus.emit 推 SSE。执行面所有动作必须经 PlatformSDK 回写控制面（门面模式），保证被审计、被护栏约束。orchestrator.run_capability 是 agent 工具调用入口，能力计数在方法本体（agent 内部调用无法绕过预算）。

③ 双循环 + 元循环编排时序

内循环做研究 → 外循环（layer_11）约束审计 Accept/Refine/Restart → 元循环（layer_09）自递归改进（冻结验证器 + 可证伪预测 + 回滚）；反馈回灌内循环下一轮。

④ 能力注册表、Agent 工具面与护栏

基础设施层 10 环节 + kaggle_eval + layer_11 审计 = 11 个注册能力。Agent 通过 PlatformSDK 调用 run_capability；内环工具白名单剔除外环/元循环能力，杜绝自证。

⑤ 平台契约生成链（前后端单一事实来源）

pydantic 模型 → export_typescript.py → zod 类型。后端校验用 pydantic，前端理论用 contracts.ts，但实际运行时使用 client.ts 手写 interface（存在漂移，见⑨）。

⑥ 前端组件树与数据获取

极简 SPA：React 18 + Vite + TS，零 UI/路由/状态库。App.tsx 自研路由 + 侧边栏；数据双通道 = REST 轮询（主）+ SSE（刷新触发器）。

前端技术栈（零依赖）： react 18.3 / react-dom / zod（仅 3 个运行时依赖）。Vite 构建；CSS 变量手写暗色主题，无 UI 库、无图表库（对比条形图/树形/时间线均用 div+CSS 手工实现）。路由靠 App.tsx 的 useState 条件渲染，状态靠 props 上抛下传，无 Redux/Zustand。SSE 仅用于打断 3s 轮询立即重拉，真正数据来自 REST 轮询。

⑦ 持久化结构

两层持久化：控制平面用 JSON 文件（Repository，原子写 + 线程锁），双循环累积记忆用 SQLite（ResearchStateStore）。自定义任务独立 JSON。

⑨ 技术债与待同步项

1. 契约漂移（重要）： platform_contracts/generated/manifest.json 落后于源码，缺 AuditReport/ImprovementProposal/HypothesisNode/ExperienceEntry 等新模型与若干事件；建议重跑 export.py + export_typescript.py 使 JSON 与 TS 完全一致。

2. 前端副本断链： frontend/src/contracts.ts 是手工复制且已漂移（如 ApprovalRequiredEvent 缺 run_id、AuditReport.constraints 类型不一致），且无任何文件 import 它。运行时真正类型是 api/client.ts 的手写 interface，zod 的 safeParse 实际未被调用（降级为 console.error）。

3. 死代码： views/BenchmarkTasks.tsx（132 行，已被 BenchmarkCatalog 取代）、src/contracts.ts；client.ts 中 getExperiences/getBenchmarkSuites/runEvolution/evaluateRun/reportRunMetric 已定义未消费。

4. 展示常量重复： STATUS_LABEL/STATUS_CLASS/DECISION_* 在 client.ts 声明为"single source of truth"，但 App.tsx / RunDashboard.tsx / DualLoopLive.tsx 各存本地副本；CATEGORY_LABELS 重复 4 份。

5. 裸 fetch 绕过封装： CompareRuns 直连 /research-records/compare、ApprovalConsole 直连 resolve-approval、deleteBenchmarkTask/uploadDataset 用裸 fetch，未走 client.ts 封装（DELETE/FormData 场景）。

6. evaluation/ 目录未承载独立模块： 评测逻辑分散在 eval_runner.py 与 kaggle_eval_executor.py，如需统一评测抽象可在此收敛。
