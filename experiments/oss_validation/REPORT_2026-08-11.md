# OSS Benchmark 实验验证报告（codex 作为 LLM Agent 替代 · tmeoa 作为 GPT-4o 替代）

日期：2026-08-11
执行环境：macOS (Apple M4 Pro, 无 NVIDIA GPU)、Codex CLI v0.133.0、tmeoa 代理 `deepseek-v4-flash-official`

## 1. 目标与方法

按用户要求，对精选外部 OSS 研究任务进行「数据收集 + 实验验证」：

- **LLM Agent 替代**：本机 `codex` CLI（OpenAI 编码智能体）替代原任务中的 GPT-4o / LLM agent，负责**生成解题程序**。
- **GPT-4o 替代**：`https://ai-rec.tmeoa.com/llmproxy/chat/completions`（`deepseek-v4-flash-official`，Bearer 鉴权）替代原任务中的 GPT-4o 调用（主要用于 SAB 的 visual judge / 模型打分）。
- **本地评分**：每个任务自带的 `evaluate_local.py` / `eval.py` / `run_eval.py` 在受控环境（单线程、managed venv）内运行并打分的「agent 写程序 → harness 跑分」闭环。

关键工程发现：
- `python`/`python3` 在 PATH 上 = 裸 managed 3.13.12（**无 sklearn/pandas**）；managed venv（`/Users/glennge/.workbuddy/binaries/python/envs/default/bin/python`）含 sklearn 1.9.0 / pandas 3.0.3 / numpy 2.4.6。
- 因此统一改为：**codex 仅负责生成 `solve.py`/优化 `solution.py`（agent 角色），由 harness 用 managed venv 运行+评分**（这也更贴合 SAB 原设计：agent 产出程序，harness 独立运行+评分）。
- codex 必须在 git 仓库内运行（否则报 `Not inside a trusted directory`）。所有验证 workspace 放在 `safety_auto_research/experiments/oss_validation/` 内。
- macOS 无 `timeout` 命令；`deepseek-v4-flash-official` 是**推理模型**，会先输出 `reasoning_content` 再输出 `content`，须把 `max_tokens` 设足（≥2000）并读取 `choices[0].message.content`。

## 2. 验证结果（已跑通的任务）

| # | 任务 (suite) | 任务类型 | codex 产出 | 评分结果 | 状态 |

| 2 | `suite.science_agent_bench` #92 (JNMF 重要性因子) | 数值分析（numpy+json） | `solve.py` 计算 6 个因子 | 与 gold 逐项误差 1.67e-16（机器精度），6 键全对 | ✅ PASS |
| 3 | `suite.science_agent_bench` #5 (DKPES 随机森林) | 监督学习（sklearn） | `solve.py` 训练 RF，阈值 0.6 二值化 | index 顺序一致 + AUROC=1.0 ≥0.91 | ✅ PASS |

## 3. 可行性矩阵（其余 OSS 任务组）

### 3.1 已确认可行 / 已验证
- **autolab（CPU 类）**：`safety_router` ✅已验证。其余大量 CPU 任务结构同类、可类推跑通，例如：`adaptive_compression, adversarial_splay, agent_tool_routing, bm25_search_go, bvh_raytracer, concurrent_kv_wal, data_select_ifeval, discover_sorting, fft_rust, fredkin_sort_network, gaussian_blur, grpo_multisource, hash_join, levenshtein_distance, llm_online_serving, moving_mnist_world_model, radix_sort, regex_engine, resnet_bit_flip, scaling_law, sha256_throughput, smallest_game_player, sstable_compaction_rs, stack_machine_golf, toy_isa_opt, vliw_scheduler, z_order_range_scan`。
- **arbor（arbor-zoo 算法调优）**：`algotune_knn` ✅已验证；其余 arbor-zoo 任务同为单线程 CPU 算法调优，结构同类。
- **science_agent_bench（SAB）**：完整 benchmark 已在 `benchmark_tasks/suites/data/vendor/ScienceAgentBench/`（3.7GB，含 datasets/eval_programs/gold_programs）。102 任务中 29 个轻量候选（pandas/numpy/matplotlib/scipy 为主）。已验证 #92、#5。其余 CSV/JSON 产出类任务可直接类推；部分需 `ccobra`/`biopsykit` 等库（可 pip 安装）。

### 3.2 本地不可行（缺 GPU / 缺大模型权重 / 缺 API）
- **autolab CUDA 任务**：`aes128_ctr, flash_attention, huffman_canonical_decode_cuda, icp_correspondence_step_cuda, msm_pippenger_bls12_381_cuda, ntt_butterfly_cuda` —— 需 NVIDIA GPU + CUDA kernel，本机无 GPU。
- **claudini**：LLM 安全攻击类，需 `Meta-SecAlign-70B` / `gpt-oss-safeguard-20b`（70B 级权重），本机无 GPU、无权重。
- **AutoResearchClaw / ARA / Auto-claude**：多数子任务依赖特定大模型 API 或 70B 级本地权重（如 `arc_bench` 等），本机无对应模型/密钥，按前期分析不可行。
- **mle_bench**：按用户要求**跳过**（不验证）。

### 3.3 tmeoa (GPT-4o 替代) 现状与限制
- ✅ 端点连通，`deepseek-v4-flash-official` 可返回 `content`（已封装为 `experiments/oss_validation/tmeoa_client.py`，OpenAI 兼容 `chat()` / `chat_text()`）。
- ⚠️ 该模型为**纯文本推理模型，无视觉能力**。SAB 中 GPT-4o 的角色是**figure 的 visual judge**（看图打分）。因此：
  - 非 figure 任务（CSV/JSON 产出，如 #92/#5）**完全不需要 GPT-4o**，本地确定性评分即可，tmeoa 不被触发。
  - figure 任务（如 #48/#49/#57）的 visual judge **无法用纯文本 tmeoa 忠实替代**（缺图像输入）。若需覆盖，须改用带视觉的模型端点，或在 eval 中改为基于文本 rubric 的弱代理（已在报告中标注为限制，未做）。

## 5. 结论与建议

1. **管线已端到端跑通**：codex（agent）→ 本地评分闭环在 3 个 suite（autolab / SAB / arbor）共 4 个任务上验证成功，覆盖「模型压缩 / 数值分析 / 监督学习 / 算法加速」四类。
2. **tmeoa 代理已就绪但受限于纯文本**：文本类 GPT-4o 调用可直接替换；视觉类 judge 需视觉模型，建议后续接入视觉端点或改为文本 rubric 弱代理。
3. **建议下一步**：(a) 对 SAB 其余 CSV/JSON 轻量任务批量跑 codex 验证（可并行多 workspace）；(b) 为 CUDA 任务申请 GPU 环境或 Harbor 沙箱；(c) 为 claudini/AutoResearchClaw 类接入对应大模型 API/权重后再验证。
